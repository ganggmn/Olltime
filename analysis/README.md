# 분석 스크립트

올타임 누리집의 「검증 기록」(/verify)에 적은 숫자를 낸 스크립트예요. 누리집에는 올라가지 않고 저장소에만 있어요.

실행하려면 `data/` 폴더에 원자료가 있어야 해요. 원자료는 용량과 이용 조건 때문에 저장소에 넣지 않았어요. 한국체육산업개발 공공데이터(입출차정보, 차량입출차·공연·날씨 연계 데이터), 서울 열린데이터광장(생활인구, 실시간 도시데이터), 서울교통공사(역별 시간대별 승하차 인원), 기상청 종관기상관측에서 받을 수 있어요. `data/` 폴더에서 `python3 ../analysis/<파일>`로 돌려요. pandas와 numpy만 써요.

| 파일 | 검증 기록 | 하는 일 |
|---|---|---|
| val.py, val2.py, val3.py, val5.py, val6.py, val7.py | 1, 2, 11 | 한 달씩 숨기고 주차장 안 차량 수를 맞히는 검증. 정보(요일, 공휴일, 공연, 지난 7일, 날씨)를 하나씩 더했을 때의 정확도. `val.py`가 먼저 돌아야 해요(`/tmp/D.pkl`을 만들어요) |
| pprof.py | 18 | 사람 수의 시간대별 모양(서울시 구역과 테두리 750m 칸, 공연 없는 월~목)과 사람 수에서 차이가 남는 비율. model.js의 PP, BETAP 값이 여기서 나와요. `lunch.py`의 앞부분(칸 고르기)을 그대로 써요 |
| edge.py | 18 | 공원 안과 테두리의 시간대별 인구를 방향별로 나눠 보는 표 |
| ladder.py | 1, 2 | 누리집에 적은 정확도 표를 그대로 다시 내는 스크립트. 정보를 하나씩 더할 때의 정확도와 평균 오차(대), 앞선 달로만 배웠을 때, 1·2·4·6시간 전 실제 값으로 고쳤을 때, 설·추석과 평일 공휴일. `val6.py`가 같은 폴더나 홈 폴더에 있어야 해요 |
| crosscheck.py | 6, 14, 15 | 옮겨 적은 값을 원자료에서 다시 계산해 맞춰 보는 스크립트. 새벽 바닥 대수, 공연 시작부터 출차가 몰릴 때까지의 시간, 역 승차 증가 합, 10분 곡선을 1시간으로 묶은 값 대 실제 |
| bt.py | 3 | 2026년 11월 13~23일 실시간 주차 대수로 다시 확인 |
| sat.py, gatep.py | 6 | 문별 출차 쏠림과 5분 상한, 문·구역별 20분 간격 주차 대수 |
| stn.py | 7 | 공연 날 역별 승하차 증가 |
| cellmap2.py | 8, 16 | 250m 칸별 공연 날 인원 증가, 공원 안팎 구역 |
| coef.py, rt3.py | 9 | 차 한 대당 방문객 수(날 종류·시간대별) |
| band.py, rec.py | 10 | 범위로만 주어지는 값을 한 숫자로 되살리기 |
| beta.py | 14 | 예상과 실제의 차이가 몇 시간 뒤에 얼마나 남는지 |
| k10.py, k11.py | 15 | 공연 끝난 뒤(시작 전) 10분별 역 승하차 몫, 문별 10분 차량 |

알아 둘 점: 대화하며 그때그때 만든 스크립트라 한 줄이 길고 주석이 적어요. 정확도는 `100 × (1 − Σ|예측−실제| ÷ Σ실제)`로 계산해요(아침 7시 이후 시간대). 지난 7일 기록은 예측하는 날보다 앞선 날만 써요(`val3.py`의 `days[max(0,i-7):i]`).

## 자동 점검

`npm test`(Node 20 이상, 설치할 것 없음)로 `tests/run.mjs`를 돌려요. 화면 코드 문법, 화면끼리 숫자가 같은지(정확도 표, 검증 기록 건수, 보정값), 운영판 계산(비례, 합산, 시각 이동), 공연 일정이 화면마다 같은지, 지하철 급행 경로, 서버 함수의 응답 형식과 실패 처리를 봐요. 예측의 정확도 자체는 여기서 다시 계산하지 않아요(원자료가 필요해서 `ladder.py`로 따로 돌려요).

## 매일 쌓이는 값으로 다시 채점하기

`node analysis/live_score.mjs 2026-11-23 2026-11-24` 처럼 날짜를 주면, 공개된 기록을 받아 '2시간 앞서 낸 예상'을 채점해 문장으로 보여 줘요. 이상 징후 기준을 주려면 `--win 10 --dn 2000 --dp 20.0 --k 3.0`을 붙여요(몇 분 사이, 몇 명, 몇 %, 평소 오차의 몇 배). 계산은 저장소 맨 위의 `model.js` 하나로 하고, 누리집의 추이 화면·운영판·서버(`/api/score`)도 같은 파일을 써요.
