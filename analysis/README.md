# 분석 스크립트

올타임 누리집의 「검증 기록」(/verify)에 적은 숫자를 낸 스크립트예요. 누리집에는 올라가지 않고 저장소에만 있어요.

실행하려면 `data/` 폴더에 원자료가 있어야 해요. 원자료는 용량과 이용 조건 때문에 저장소에 넣지 않았어요. 한국체육산업개발 공공데이터(입출차정보, 차량입출차·공연·날씨 연계 데이터), 서울 열린데이터광장(생활인구, 실시간 도시데이터), 서울교통공사(역별 시간대별 승하차 인원), 기상청 종관기상관측에서 받을 수 있어요. `data/` 폴더에서 `python3 ../analysis/<파일>`로 돌려요. pandas와 numpy만 써요.

## 자동 점검

공연 일정은 `api/_shows.js`가 올림픽공원 누리집 일정안내를 읽어 날짜별 시작 시각으로 풀어요(`/api/shows`). 누리집의 실제 시각 문장은 `tests/fixtures/shows_site_2026-11-26.json`에 있어요(2026년 11월 26일에 받은 것. 시각 문장은 그대로이고, 공연 제목 몇 개는 뒷부분을 줄이거나 다듬어 적었어요).

`npm test`(Node 20 이상, 설치할 것 없음)로 `tests/run.mjs`를 돌려요. 화면 코드 문법, 화면끼리 숫자가 같은지(정확도 표, 검증 기록 건수, 보정값), 운영판 계산(비례, 합산, 시각 이동), 공연 일정이 화면마다 같은지, 지하철 급행 경로, 서버 함수의 응답 형식과 실패 처리를 봐요. 예측의 정확도 자체는 여기서 다시 계산하지 않아요(원자료가 필요해서 `ladder.py`로 따로 돌려요).

## 매일 쌓이는 값으로 다시 채점하기

`node analysis/live_score.mjs 2026-11-23 2026-11-24` 처럼 날짜를 주면, 공개된 기록을 받아 '2시간 앞서 낸 예상'을 채점해 문장으로 보여 줘요. 이상 징후 기준을 주려면 `--win 10 --dn 2000 --dp 20.0 --k 3.0`을 붙여요(몇 분 사이, 몇 명, 몇 %, 평소 오차의 몇 배). 계산은 저장소 맨 위의 `model.js` 하나로 하고, 누리집의 추이 화면·운영판·서버(`/api/score`)도 같은 파일을 써요.

## KOPIS 티켓 판매수 (api/kopis.js, scripts/fetch_kopis.py)
- 출처: 공연예술통합전산망(KOPIS) 공연시설별 통계(prfstsPrfByFct). 키는 Vercel 환경변수 `KOPIS_KEY`에만 있고, 스크립트는 올타임 서버를 거쳐 받아요.
- 서버는 시설 이름을 정해 둔 목록(올림픽공원 등)에서만, 기간은 31일까지만 받아요.
- `fetch-kopis.yml`을 test로 돌리면 공연 날·공연 없는 날·이번 주 날짜를 하루씩 받아, 판매수가 공연일 기준인지 예매일 기준인지와 공연 전에도 나오는지를 봐요(analysis/kopis_test.json).
- 2025로 돌리면 2025년 모든 날을 하루씩, 달마다 받아 kopis_daily_2025.csv, kopis_monthly_2025.csv로 저장해요.
- `kopis_size.py`(맥 data 폴더에서 실행): 2025년 KSPO DOME 공연 날 판매수와 서울시 올림픽공원 영역 인원 증가를 맞대고, 판매수로 크기를 정하는 모델(T)을 지난 달들만으로 배워 채점해요.
  결과(2026-11-26): 판매수 중간 50%가 8,686~10,627매로 좁고, 같은 공연 이어진 날의 판매수 차이는 중앙값 33매뿐이에요.
  평일 공연은 판매수와 공연 앞뒤 3시간 증가의 상관이 0.75(표 한 장당 약 0.6명)지만 주말은 0.45예요.
  판매수를 정확히 알아도 첫날 정확도는 82.5% → 82.9%로 거의 그대로예요. 크기를 정하는 건 판매수보다 팬들이 오는 방식(표 없이 오는 사람, 일찍 오는 정도)으로 보여요.
  같은 가수의 앞선 공연(2025년 안) 보정은 4일뿐이지만 84.0% → 89.0%예요.
- `radius.py`(맥 data 폴더에서 실행): 올림픽공원역→KSPO DOME 선분 둘레 r m(0·150·300·450·600) 칸만 떼어 첫날 공연을 맞혀 봐요. 공원 전체를 구역 몫과 나머지로 나눠 맞히는 것도 같이 봐요.
  결과(2026-11-26): DOME 칸 하나에 첫날 공연 증가의 50%가 몰리고, 첫날 오차의 49%도 거기서 나와요. 300m 안은 증가 74%, 오차 76%예요.
  나눠 맞혀도 공원 전체 첫날 정확도는 83.5% → 83.4%로 그대로예요. 오차가 나들이객이 아니라 관객 무리 자체에서 나기 때문이에요.
  같은 2025년 첫날 35일에서, 당일 실시간 보정을 하면 2시간 앞 89.5%, 1시간 앞 93.4%예요(하루 전 예측은 82.5%).
  공연 일수가 6일 이상인 공연의 첫날은 필요한 크기 배율이 1.77배(5일)예요. 이것으로 고쳐도 83.0%이고, 판매수(공연 뒤에 아는 값)로 고쳐도 83.6%예요.
- `patterns.py`(맥 data 폴더에서 실행): 2024·2025년 KSPO DOME 공연 날 212일을 오륜동 생활인구(성별·나이 포함)로 같은 잣대로 보고, 미리 알 수 있는 특징별로 크기·모양이 갈리는지 봐요.
  공연 목록·시각·가격은 KOPIS 상세(kopis_meta_2024_2025.csv)에서 받아요. 2025년 오륜동은 서울시 올림픽공원 영역과 상관 0.91~0.95라 2024년 대신 써도 돼요.
  결과(2026-11-26):
  - 두 해 공통: 17시 이후 시작 공연은 시작 1시간 전이 가장 붐비고, 낮 공연은 시작 시각에 가장 붐벼요.
  - 판매수 1만1천 매 넘는 공연은 크기 1.49·1.39배, 8천 매 미만은 0.86·0.77배예요.
  - 같은 날 다른 공연장에 5천 매 넘게 팔린 날은 더 붐비고(1.38·1.04배), 없는 날은 덜 붐벼요(0.60·0.76배).
  - 관객 나이, 회차, 공연 일수, 가격, 계절은 두 해 방향이 엇갈려요.
